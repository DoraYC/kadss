# KADSS · 供应链齐套预警与动态安全库存优化

## 项目背景

离散制造普遍存在多品种、小批量、多层 BOM 与共享料并存的情况。供应计划要在有限库存下回答三个问题：哪些物料需要重点管理、哪些订单无法齐套、安全库存该定多少。ERP/MES 通常能提供物料、BOM、库存与采购记录，但缺少把这些数据转成分层策略、缺料预警和库存-缺料权衡的统一视图。

实际业务中，物料常被套用同一套固定安全库存和固定提前期；缺料往往等到排产或开工才暴露；库存金额与缺料风险分散在不同报表，难以量化比较。本项目用 Python 生成的可复现模拟数据，完整跑通“数据生成 → ABC-XYZ 分层 → 动态安全库存 → BOM 齐套 → 齐套概率 → 成本仿真 → 看板呈现”，并通过正常、高波动、交期恶化三个场景观察策略在需求波动与交期变化下的表现。

项目不接入真实 ERP/MES，也不替代生产级排产系统；目标是把计算口径、策略对比和看板表达做成可运行、可核对、可复现的样例，供计划人员演示缺料风险与补货建议，也供库存管理者在同一口径下比较固定与动态安全库存的库存占用和缺料风险。

<br />

## 项目说明

面向离散制造的计划辅助系统：用模拟数据驱动 ABC-XYZ 分层、动态/固定安全库存、订单齐套预警、齐套概率与库存-缺料成本对比，并通过 Streamlit 看板只读展示。

预计算结果已随仓库提交，克隆后可直接启动看板；需要改数据或参数时再运行批处理命令重建。

## 看板内容

| 页面   | 内容                                     |
| ---- | -------------------------------------- |
| 物料分层 | ABC-XYZ 矩阵、分层明细、数据置信度                  |
| 齐套预警 | 订单齐套结论、缺口金额/物料数、齐套概率、风险等级、单订单缺口与交期分布假设 |
| 库存策略 | 三档服务水平的动态/固定安全库存、建议补货量与金额、交期来源         |
| 成本对比 | 固定 vs 动态策略的库存金额、持有成本、缺料成本、物料/订单缺料率与差异  |

顶部固定展示 `run_id`、场景、随机种子、基准日期与数据规模；侧边栏可切换场景、可用量口径、服务水平、惩罚系数、模拟次数与筛选条件。

## 快速开始

要求 Python 3.12+（本地验证环境为 3.14）。

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

streamlit run app.py
```

打开 <http://localhost:8501> 即可。默认使用 `small` 规模（200 物料）；看板侧边栏可切换到已生成的 `large` 规模。看板启动时会校验 5 张结果表的 `run_id` 与当前配置、基础数据是否一致；不一致会拒绝启动并提示重建。

## 数据规模（profile）

规模只由配置选择，代码中不切换。`small` 为默认演示规模，`large` 用于性能验收与面试演示：

| 规模 | 物料 | 需求订单 | 历史需求（物料×天） | BOM 平均层级 | 输出目录 |
| --- | --- | --- | --- | --- | --- |
| `small`（默认） | 200 | 50 | 90 天 / 17,520 行 | 1.93 | `data/`（随仓库提交） |
| `large` | 2,000 | 300 | 180 天 / 349,800 行 | 3.18 | `data_large/`（按需生成，不入库） |

历史需求是每个物料每天的日需求记录，用于安全库存 `σ_d` 与 ABC-XYZ 周度 CV，**不是订单行**；300 个需求订单在 `t_kadss_demand_order` 中只有 300 行。前者按「物料 × 天」连续记录（含零需求日），后者按订单记录，两者粒度不同，不能直接用订单数乘天数推算。

生成大规模数据：

```bash
python -m kadss.build_dataset --profile large --scenario normal
python -m kadss.build_results --profile large --scenario normal
```

生成后在侧边栏「数据规模」切到「大规模（2,000 物料）」即可查看。三个场景都演示时把 `--scenario normal` 换成 `--scenario all`（约 50 秒）。`data_large/` 已在 `.gitignore` 中忽略，避免把大文件提交到仓库；默认规模不受影响。

最近一次大规模实测：生成与落库 10.44 秒，计算 5 张结果表 11.03 秒，全流程 21.47 秒。

## 常用命令

```bash
# 重新生成三个场景的基础数据（会重建 SQLite 并导出 CSV）
python -m kadss.build_dataset --scenario all

# 重新计算三个场景的结果表（须在 build_dataset 之后执行）
python -m kadss.build_results --scenario all

# 只处理单个场景
python -m kadss.build_dataset --scenario normal
python -m kadss.build_results --scenario normal

# 运行测试
python -m unittest discover -s tests -v
```

执行顺序固定为 `build_dataset` → `build_results`，因为前者会重建数据库。结果表重建后 `run_id` 变化，看板缓存自动失效。

## 数据与口径

- **场景**：`normal`（正常）、`high_volatility`（高波动）、`leadtime_deterioration`（交期恶化），每场景一个 SQLite 库。
- **数据版本**：`run_id = <scenario>-<参数哈希12位>-<基础数据摘要8位>`；5 张结果表只保留当前 `run_id`。
- **可用量**：当前库存 + 在途 − 已分配，可选再扣质检锁定与安全库存。勾选安全库存时恒扣默认 95% 档位的动态安全库存。
- **缺口**：`gap_qty = max(需求 − max(可用量, 0), 0)`；共享料按 `(required_date, order_id)` 先到先得单遍分配。
- **缺料率**：`物料缺料率（按行数）` 与 `订单缺料率（按订单数）`，文案与口径统一取自 `kadss/labels.py`。
- **齐套概率**：只读 baseline @ 默认服务水平；任一物料低置信则该订单概率为空、风险为“数据不足”。
- **策略对比**：固定/动态策略扣对应档位安全库存，每个 `(strategy, service_level)` 组合都从初始库存独立重算。

## 配置

所有阈值、档位、Z 值、种子与场景差异都来自 `config/kadss.json`：

| 配置段            | 关键项                                    |
| -------------- | -------------------------------------- |
| `profiles` | `small` / `large` 两套规模，含物料数、订单数、历史天数与输出目录 |
| `scale` | 当前 `profile` 的物料数、需求订单数、历史天数（由 `profiles` 解析） |
| `scenarios`    | 需求波动倍数、交期延误均值/标准差、种子偏移                 |
| `abc_xyz`      | A/B 累计金额分界 0.7/0.9、X/Y 的 CV 分界 0.1/0.25 |
| `noise`        | 零需求 5%、尖峰 1%×3、波动类型占比 X/Y/Z = 10%/40%/50% |
| `safety_stock` | 服务水平 90/95/99、默认 95、Z 值、固定覆盖天数 7       |
| `probability`  | 模拟次数 100、风险阈值 0.9/0.7                  |
| `cost`         | 年持有成本率 20%、惩罚系数 3.0、仿真 90 天            |

看板控件只把值作为函数入参，不内置常量表；新增参数先入 `kadss/config.py` 的 `DEFAULTS`，再写入配置文件。

## 缓存与重算边界

- 场景切换只切换数据库，不触发生成或计算。
- 看板参数变更只在内存重算，不写回 SQLite。
- 缓存键：`run_id + 可用量口径 + 服务水平 + 惩罚系数 + 模拟次数`；ABC-XYZ 只随场景库变化。
- 默认参数直接复用落盘结果，因此首屏与筛选切换无需重算。

## 部署到 Streamlit Community Cloud

1. 将仓库推到 GitHub，确认 `data/`、`config/`、`requirements.txt` 已提交。
2. 在 <https://share.streamlit.io> 新建 App，选择仓库与 `main` 分支，主文件填 `app.py`。
3. Python 版本选择 Cloud 当前支持的最新版本（本地验证为 3.14；若不可选，用 Cloud 提供的最新 3.x）。
4. 直接 Deploy。`data/` 内已包含三个场景的预计算库，无需在云端重跑批处理。
5. 若之后修改配置或数据，需本地重新执行 `build_dataset` → `build_results`，并提交新的 `data/`；否则看板会因 `run_id` 不匹配而拒绝启动。

## 5 分钟演示路径

1. **物料分层**：看 ABC-XYZ 矩阵，指出样本不足物料不强行分层并标注置信度。
2. **齐套预警**：按缺口金额排序，任选订单查看缺口物料、交期均值/标准差与来源。
3. **库存策略**：95% 服务水平下看建议补货 Top 10，说明动态与固定安全库存差异。
4. **成本对比**：调整惩罚系数，观察缺料成本变化，再看动态相对固定的库存金额与缺料率差异。
5. **场景切换**：从正常切到高波动或交期恶化，对比 KPI、缺口与齐套概率变化。

## 适用边界

- 面向离散制造与装配型场景；流程制造需结合批次、配方与工艺参数重新建模。
- MVP 只计算理论可用量，不区分物理批次、库位与保质期。
- 成本参数、风险阈值与服务水平均为可配置假设值，不构成采购承诺。
- 齐套概率按订单整体展开 BOM 计算，不做组件级 MRP 净需求计划。
