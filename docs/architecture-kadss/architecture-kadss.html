02

计算管道

离线批处理按固定顺序执行，结果落盘；看板只消费结果或在内存中做参数化重算。

STEP 01abc_xyz

ABC-XYZ 分层

按消耗金额累计占比分 ABC，按周聚合需求的变异系数分 XYZ；样本不足的物料不强行分层。

CV = σ_weekly / avg_weekly；A ≤ 70%，B ≤ 90%
STEP 02safety_stock

动态安全库存

采购件取历史实际交期偏差；自制/外包件回退标准提前期并标记 lt_source。三档服务水平批量输出。

SS = Z × √(LT_avg × σ_d² + d_avg² × σ_LT²)
STEP 03kitting

BOM 齐套分析

多层递归展开，共享料按需求日期先到先得；替代料只标记不参与计算，缺口按可用量口径计算。

gap = max(毛需求 − max(可用量, 0), 0)
STEP 04probability

齐套概率

以总提前期分布为随机输入做蒙特卡洛；含低置信物料的订单输出 null 与“数据不足”。

P = 全部缺口物料在 required_date 前到货的模拟占比
STEP 05cost

库存成本仿真

固定与动态策略使用同一组需求与交期抽样，保证可比；输出库存金额、持有成本、缺料成本。

缺料成本 = 缺料数量 × 单价 × 惩罚系数
STEP 06pipeline

结果落盘

计算 run_id，清空并重写 5 张结果表；看板按场景读取，不跨 run 聚合。

run_id = scenario + 参数哈希 + 基础数据摘要
口径权衡
高服务水平 ≠ 所有指标都变好：它降低缺货成本，但提高库存占用与可用量约束。策略对比中的缺料率按“预留安全库存后的可用量”计算，与缺料成本方向可能相反。
03

依赖方向

依赖方向本身就是规则：展示层可以依赖计算层，计算层不得反向依赖展示层或数据库驱动。

允许的依赖

  • app.py → kadss.* 计算函数与常量
  • app.py → kadss.store 的只读查询
  • kadss.build_* → kadss.*
  • kadss.pipeline → 各计算模块
  • kadss.store / pipeline → sqlite3

禁止的依赖

  • 计算模块 → streamlit / app
  • 计算模块 → sqlite3（读写都走 store / pipeline）
  • 任何模块把 CSV 读回作为输入
  • 看板内出现安全库存、缺口、概率、成本公式
  • 结果表跨 run_id 或跨场景聚合
04

九条不变量

每条都满足三个条件：两个单元独立实现时可能冲突、选择不显然、且是真实取舍。已确立 表示由 PRD 决策或现有实现确立；需落实 表示本次新定。

AD-1

分层边界：展示层不得持有业务公式

已确立
约束
全部模块；US-1 ~ US-7
防止
看板自建数据或复写公式，导致页面结论与批算结果、报告摘要不一致。
规则
只允许 app.py → kadss.*、kadss.build_* → kadss.*、pipeline → 计算模块、store/pipeline → sqlite3。计算模块不得 import streamlit、app 或 sqlite3；看板不得出现安全库存、缺口、概率、成本等公式。
AD-2

持久化契约：SQLite 单一主源，run_id 覆盖写

需落实
约束
US-1、US-4、US-6；6 张基础表与 5 张结果表
防止
CSV 与 DB 双写漂移；旧参数结果混入看板；三个场景串库。
规则
  • 基础表只经 store.write_dataset 写入，结果表只经 pipeline.write_results 写入；CSV 只从 SQLite 导出，不得读回。
  • 每场景一库，路径固定 data/<scenario>/kadss.db，场景名只来自配置。
  • run_id 只由 pipeline 计算；参数哈希覆盖 seed、base_date、abc_xyz、safety_stock、kitting、probability、cost。
  • 清空与写入同一事务，提交前断言 5 张结果表的 run_id 一致；读取基础表按主键排序后再算摘要。
  • 读库前自检 5 张结果表 run_id 一致且与配置的 seed、base_date 匹配，不一致拒绝启动。
  • 执行顺序固定：build_dataset → build_results。
AD-3

计算口径单点实现

需落实
约束
US-2 ~ US-6
防止
同一指标多处实现后产生偏差（可用量、缺口、Z 值、缺料率最易分叉）。
规则
每个业务量只有一个实现位置：ABC/XYZ → abc_xyz；安全库存与建议补货量 → safety_stock；BOM 展开与共享料分配、缺口 → kitting；概率与风险分级 → probability；成本 → cost；可用量 → kadss.availability；订单状态与物料/订单缺料率 → kadss.metrics（gap_rates 从 build_results 迁出）。新建两个模块一次性收口 safety_stock、cost、probability、kitting.order_status 的重复实现，作为看板接入的硬前置。
AD-4

配置是唯一参数面

已确立
约束
US-1、US-3、US-6、US-7；全部阈值、档位、种子与场景差异
防止
看板硬编码 Z 值或场景参数，与 config/kadss.json 漂移。
规则
阈值、服务水平、Z 值、惩罚系数、模拟次数、种子、场景参数只能来自 load_config()；DEFAULTS 仅作兜底。新增参数先入 DEFAULTS 再入 JSON。看板控件只把值作为函数入参，不得内置常量表或复制场景定义。
AD-5

指标文案唯一来源

已确立
约束
US-6、US-7、D-1、D-7
防止
看板、报告与文档对缺料率及口径说明的表述不一致。
规则
物料缺料率（按行数）、订单缺料率（按订单数）、策略口径说明与权衡说明只能引用 kadss.labels；禁止内联字符串；禁止只写“缺料率”。空间受限时只允许 物料缺料率(行)、订单缺料率(单)。
AD-6

置信度单向传播

已确立
约束
US-2、US-3、US-5
防止
各模块自行判定低置信，导致同一物料在不同页面结论不同。
规则
低置信只由两处判定：ABC 的 active_weeks < min_periods、安全库存的日需求或交期样本不足；pipeline._confidence_map 合并后注入齐套明细，下游只消费不重算。任一低置信物料 → 订单概率 null、风险“数据不足”、不参与排序。分层、安全库存、齐套与成本明细必须显示“数据置信度：低”，数值保留但标注，不得剔除后冒充完整结论。
AD-7

共享料分配与策略口径隔离

需落实
约束
US-4、US-6
防止
共享料被各订单重复使用；不同策略或服务水平档位污染可用量；默认口径与策略口径混用。
规则
  • 订单按 (required_date, order_id) 升序单遍分配；每个 (strategy, service_level) 组合都从初始库存重新开始。
  • gap_qty = max(req_qty − max(available_qty, 0), 0)；分配后 remaining = max(available_qty − req_qty, 0)；展开后按物料聚合，保证 (order_id, material_id) 唯一。
  • baseline 不扣安全库存，只用于默认展示与概率；fixed / dynamic 扣对应策略安全库存，只用于策略对比。
  • BOM 只取 is_substitute = 0 且 version = 'V1' 的父子行；MVP 不按 effective_date 过滤、不展开 is_phantom。库存按物料唯一读取，计算前断言快照唯一。
AD-8

确定性与可复现

已确立
约束
KPI-1、KPI-2、US-3、US-5、US-6
防止
同一配置重跑结果漂移；看板刷新后结论变化；run_id 失真。
规则
随机性只经 seed（主种子 + 场景偏移）派生；按实体派生时使用稳定标识（如 zlib.crc32），不得用行号或时间。落盘数据不得使用运行时 now()：基础表取业务事件日期，结果表统一取 base_date 00:00:00。同配置重复运行逐行一致、run_id 相同；两策略共享同一组抽样。
AD-9

看板只读边界与重算范围

需落实
约束
US-4、US-7、KPI-3、KPI-4
防止
看板现场重跑全流程导致卡顿；或死读落盘数据无法响应口径勾选。
规则
  • 场景切换只切换 SQLite 库，不触发生成或计算。
  • 参数变更只能调用 kadss 函数在内存重算。缓存键固定为 run_id + 可用量口径 + 服务水平 + 惩罚系数 + 模拟次数（顺序固定）；ABC-XYZ 分层单独以 run_id 作一级缓存键。
  • 勾选“安全库存”恒扣 default_service_level 的 dynamic_ss，标注口径，不与落盘 baseline 混用。
  • 重算范围：可用量口径 → 齐套与缺料率；服务水平 → 安全库存与成本；惩罚系数/模拟次数 → 成本与概率；分层只随场景库变化。
  • 重算结果不写回 SQLite；顶部版本信息取 run_id 与配置中的 seed、base_date、scale。
  • 看板不得自建假数据或近似公式；现有 demo 数据路径必须移除。
05

数据模型与 ER 图

6 张基础表以物料主数据为中心，BOM 通过 parent / child 双外键关联；5 张结果表以 run_id 为版本维度。表名统一 t_kadss_ 前缀。

PK 主键 · FK 外键 · 连线为物料 → 引用它的表（1 : N）。BOM 通过 parent_material_id / child_material_id 两个外键引用物料；其余 4 张表均以 material_id 关联。结果表字段与粒度见下表。
BASE TABLES · 6

08

边界与决策

三条已拍板的决策，以及明确不做的边界。当前无未决阻塞项。

TD-1 · 已确认

随仓库提交预计算 SQLite

三库合计约 9.7 MB，提交后冷启动即读，目标 ≤ 30 秒由此满足。同步移除 .gitignore 对 data/**/kadss.db 的忽略，并在读库前自检 run_id 与配置一致，防止提交过期快照。

TD-2 · 已确认

合并公共口径模块

新建 kadss/availability.py 与 kadss/metrics.py，一次性收口可用量、订单状态与物料/订单缺料率；作为看板接入的硬前置，同时完成缺料率的 API 化。

TD-3 · 已确认

五维缓存键 + 分层单独缓存

重算键固定为 run_id + 可用量口径 + 服务水平 + 惩罚系数 + 模拟次数，顺序固定；ABC-XYZ 分层只随场景库变化，单独以 run_id 缓存。先实测，未达 3 秒阈值前不做口径矩阵预计算。

Deferred · 本层不决定的事

  • 自动化测试与 CI：口径已单点收敛，补测试不改架构。
  • KPI-2 核对产物：20 单手工/Excel 核对暂无导出脚本，补 audit 导出与测试夹具即可。
  • 5,000 物料 / 10 万行需求容量优化：先按 KPI-3 实测，再决定分块或向量化。
  • 虚拟件展开与 BOM 多版本选择：字段已预留，MVP 固定单版本；实现时新增 AD。
  • 需求预测、APS、多工厂多仓、权限、推送、自然语言问答：PRD 明确为 v2.0 候选。
  • 敏感性分析的产品化呈现：当前按三档服务水平输出，交互形态未定。
  • 打包与发布形态：保持仓库内可导入包，不做 PyPI 发布。
口径声明

策略对比中的缺料率按“预留安全库存后的可用量”计算；缺料成本按实际缺货损失计算。服务水平提升会降低缺货成本，但提高库存占用与可用量约束，两个指标方向可能相反，这是权衡，不是矛盾。

看板与报告必须使用完整指标名：物料缺料率（按行数）、订单缺料率（按订单数），不得只写“缺料率”。
